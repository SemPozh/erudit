# Задачи проекта ERUDIT

## Структура

- `tasks/todo/` — открытые задачи (не начаты / в работе).
- `tasks/done/` — выполненные задачи.

## Как работать с задачами

### Нумерация

- Каждая задача — отдельный файл `N.md`, где `N` — уникальный номер.
- Новые задачи получают номер = максимальный существующий номер + 1.
- Задача содержит: **название, исполнитель, описание, номер**.

### Заведение задачи

1. Создать файл `tasks/todo/N.md` по шаблону ниже.
2. Задача автоматически оказывается в конце списка todo (самый большой номер).
3. Зафиксировать в коммите. Если задача создаётся под работу — вместе с её веткой/MR.

### Выполнение задачи

1. Работаем по **trunk-based**: ветка от `main` → задача → PR в `main`.
2. **Каждая задача — отдельный MR.**
3. Объём кода задачи — **не более ~1000 строк** (контролируйте при планировании).
4. В своём MR перенести файл задачи из `todo` в `done`:
   `git mv tasks/todo/N.md tasks/done/N.md`
5. Задача считается выполненной только при:
   - зелёных проверках CI;
   - покрытии ключевых сценариев тестами;
   - прохождении ревью.

> Монолит: сейчас пишем один Spring Boot модуль (`com.erudit`). Домен «будущий
> микросервис» в задаче — это ориентир, куда код логически относится при будущем
> разбиении. Пакеты внутри монолита можно разделять по доменам.

## Исполнители

| Исполнитель | Домены (будущие микросервисы) |
|-------------|--------------------------------|
| Илья | erudit-gateway*, erudit-ai-platform, erudit-payment, инфраструктура |
| Дестини | erudit-admin, erudit-user, erudit-quiz |
| Семен | erudit-event-reciever, erudit-content, erudit-notificator |

\* erudit-gateway на этапе монолита не разрабатывается.

- **Связанные требования:** REQ ...
