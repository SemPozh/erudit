# Задача 99. Удаление legacy-монолита и проверка границ

- **Лабораторная:** ЛР2
- **Исполнитель:** Дестини
- **Сервис:** `all services`
- **Статус:** done
- **Оценка изменений:** до 1600 строк, generated-код не считается
- **Зависит от:** 92, 93, 95, 96, 98

## Цель

Удалить временный legacy module после достижения функционального паритета.

## Что сделать

1. Сверить все legacy controllers/services/jobs/migrations с владельцами и удалить дубликаты.
2. Добавить ArchUnit rules: controller→service→repository, запрет cross-service imports и shared business models.
3. Проверить отсутствие единого datasource, monolith image и прямых URL вместо discovery.
4. Сохранить историю задач и документацию, обновив пути файлов.

## Критерии готовности

- [x] Корневой build не содержит legacy application.
- [x] Список gateway paths совпадает с утверждённым OpenAPI.
- [x] Поиск не находит JWT/Spring Security, real notification sender или cross-database access.

## Общие ограничения ЛР2

- Авторизацию, JWT, Spring Security и проверки ролей не добавлять.
- Реальные email, push и SMS не отправлять; это относится к ЛР4.
- Не обращаться напрямую к БД другого сервиса и не переиспользовать его Entity.
- Внешние HTTP DTO задаются OpenAPI; generated-код не коммитится.
- Если фактический diff достигает 1800 строк, остаток вынести в новую задачу до PR.

## Проверка

- Unit-тесты для новой логики; integration/Testcontainers для данных и HTTP.
- Запустить проверки изменённых модулей и корневые `./gradlew test openApiValidate build`.
- Проверить запуск изменённых контейнеров и соответствие `docs/lab2-architecture.md`.
