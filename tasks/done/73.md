# Задача 73. Базовый Docker Compose для инфраструктуры ЛР2

- **Лабораторная:** ЛР2
- **Исполнитель:** Илья
- **Сервис:** `platform`
- **Статус:** done — Compose, документация и обязательный CI smoke реализованы
- **Оценка изменений:** до 1100 строк, generated-код не считается
- **Зависит от:** 68, 69, 70

## Цель

Подготовить Compose-каркас, на который будут добавляться бизнес-сервисы.

## Что сделать

1. Добавить Config Server, Eureka, Gateway и сети `edge`/`internal`.
2. Настроить health-based startup, restart policy, profiles и именованные volumes.
3. Не публиковать наружу порты бизнес-сервисов в финальном профиле; для отладки использовать отдельный profile.
4. Добавить `.env.example` без секретов.

## Критерии готовности

- [x] Инфраструктура стартует одной командой и достигает healthy.
- [x] Gateway ждёт Config/Eureka через healthcheck, а не sleep.
- [x] После рестарта registry и gateway восстанавливаются автоматически.

## Реализация и проверка (2026-11-03)

- Добавлены сети `edge` и изолированная `internal`; только Gateway входит в обе.
- Config Server → Eureka → Gateway запускаются через healthy dependencies и имеют restart policy.
- Монолит и его БД вынесены в переходный профиль `legacy`; будущие бизнес-сервисы не публикуют порты.
- Добавлены `.env.example`, инструкция и smoke запуска/рестарта инфраструктуры.
- Compose default/legacy и синтаксис PowerShell проверены локально. Docker Engine локально недоступен; обязательная CI job `infrastructure-smoke` выполняет полный запуск и рестарт до merge.

## Общие ограничения ЛР2

- Авторизацию, JWT, Spring Security и проверки ролей не добавлять.
- Реальные email, push и SMS не отправлять; это относится к ЛР4.
- Не обращаться напрямую к БД другого сервиса и не переиспользовать его Entity.
- Внешние HTTP DTO задаются OpenAPI; generated-код не коммитится.
- Если фактический diff достигает 1800 строк, остаток вынести в новую задачу до PR.
