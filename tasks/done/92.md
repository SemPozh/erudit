# Задача 92. Изоляция баз и перенос Flyway-миграций

- **Лабораторная:** ЛР2
- **Исполнитель:** Семен
- **Сервис:** `data platform`
- **Статус:** done
- **Оценка изменений:** до 1600 строк, generated-код не считается
- **Зависит от:** 74–90

## Цель

Завершить физическое разделение данных по владельцам.

## Что сделать

1. Разнести legacy migrations по сервисам с новой baseline стратегией.
2. Создать отдельные database/user в PostgreSQL и минимальные grants.
3. Удалить межбазовые FK; ссылки на чужой домен хранить как UUID/value и проверять через API.
4. Добавить архитектурный тест, запрещающий datasource/repository чужого домена.

## Критерии готовности

- [x] Каждый сервис стартует при отключённых остальных бизнес-БД.
- [x] Flyway history независима для каждого сервиса.
- [x] Compose credentials разделены, а тесты используют отдельные Testcontainers/database.

## Общие ограничения ЛР2

- Авторизацию, JWT, Spring Security и проверки ролей не добавлять.
- Реальные email, push и SMS не отправлять; это относится к ЛР4.
- Не обращаться напрямую к БД другого сервиса и не переиспользовать его Entity.
- Внешние HTTP DTO задаются OpenAPI; generated-код не коммитится.
- Если фактический diff достигает 1800 строк, остаток вынести в новую задачу до PR.

## Проверка

- Unit-тесты для новой логики; integration/Testcontainers для данных и HTTP.
- Запустить проверки изменённых модулей и корневые `./gradlew test openApiValidate build`.
- Проверить запуск изменённых контейнеров и соответствие `docs/lab2-architecture.md`.

## Реализация

- Семь отдельных PostgreSQL databases/ролей; bootstrap credentials отделены от
  приложения, login без superuser/createdb/createrole/replication, минимальные grants.
- TCP/password healthchecks и project-specific Docker networks; разные Compose
  проекты больше не разделяют DNS aliases. Payment стартует без User database.
- Event Receiver использует собственную V1 Flyway migration; baseline 0 сохраняет
  квитанции прежнего schema.sql. Остальные сервисы не baseline-ят legacy schemas.
- Архитектурный guard запрещает cross-service Java/Gradle зависимости, внешние FK,
  чужие datasource defaults и общие имена сетей Compose.
- PostgreSQL Testcontainers проверяют все семь наборов миграций, повторный migrate,
  ограничения прав, запрет connect к чужим БД и сохранение старой event-квитанции.
- `test openApiValidate build`: 301 тест, без ошибок и пропусков.
- `scripts/smoke-database-isolation.ps1`: все семь сервисов healthy с собственной
  Flyway history и обычной ролью при выключенных остальных бизнес-БД; тестовый
  проект/сеть/тома удалены. Исходные данные сохранены.
- Baseline и переход существующих томов: `docs/database-isolation.md`.
