# Задача 1. Каркас API: формат ответа, обработка ошибок, DTO-маппинг

- **Исполнитель:** Илья
- **Домен (будущий микросервис):** erudit-gateway
- **Статус:** done
- **Связанные требования:** NFR 10, 11

## Описание

Заложить единый каркас для всех REST-эндпоинтов монолита: стандартный формат ответа,
глобальная обработка исключений, единый набор бизнес-ошибок и конвенции DTO-маппинга.
Это базовая задача, от которой зависит остальной код.

## Что должно получиться

- Единая обёртка ответа API (данные / ошибка / метаданные пагинации).
- `@RestControllerAdvice` для глобальной обработки исключений и маппинга их в HTTP-статусы.
- Набор типовых бизнес-исключений (NotFound, Conflict, Validation, Forbidden, Unauthorized).
- Договорённость по маппингу entity ↔ DTO.

## Критерии готовности

- [x] Все эндпоинты возвращают единый формат ответа.
- [x] Исключения маппятся в корректные HTTP-статусы и понятные тела ошибок.
- [x] Обработка ошибок покрыта тестами.
