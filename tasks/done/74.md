## Цель

Извлечь основной user-домен с собственной БД и прежними внешними контрактами.

## Что сделать

1. Перенести регистрацию, истечение verification данных и подтверждение email как локальную заглушку без реальной отправки; для demo дать известный токен.
2. Перенести профиль, обновление/удаление аккаунта, настройки и поиск пользователей.
3. Перенести только user Flyway-миграции и Spring Data JPA/JDBC repositories; добавить seed demo-пользователя.
4. Сохранить `X-User-Id` с default demo UUID; токены и пароли для login не реализовывать.

## Критерии готовности

- [x] User service запускается без legacy database.
- [x] HTTP и repository integration tests работают через PostgreSQL Testcontainers.
- [x] Все user paths доступны через Gateway без Authorization.

## Реализация

- Добавлены собственная PostgreSQL-схема, demo user и локальный verification token.
- OpenAPI покрывает регистрацию, подтверждение, профиль, поиск и настройки.
- Gateway использует существующий user route; Security/JWT отсутствуют.

## Общие ограничения ЛР2

- Авторизацию, JWT, Spring Security и проверки ролей не добавлять.
- Реальные email, push и SMS не отправлять; это относится к ЛР4.
- Не обращаться напрямую к БД другого сервиса и не переиспользовать его Entity.
- Внешние HTTP DTO задаются OpenAPI; generated-код не коммитится.
- Если фактический diff достигает 1800 строк, остаток вынести в новую задачу до PR.
