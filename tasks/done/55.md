# Задача 55. Внутренний публикатор событий

- **Исполнитель:** Семен
- **Домен (будущий микросервис):** erudit-event-reciever
- **Статус:** done
- **Связанные требования:** REQ 9.8

## Описание

Создать внутренний публикатор событий, через который другие домены монолита (контент,
квизы, нотификации, оплата) публикуют события аналитики. Используется задачами 22, 35, 39, 52.

## Что должно получиться

- Внутренний интерфейс публикации события.
- Общий путь публикации (валидация + запись в ClickHouse).
- Документация по использованию для остальных доменов.

## Критерии готовности

- [x] Домены публикуют события через единый интерфейс.
- [x] События попадают в ClickHouse.
- [x] Покрыто тестами.

## Привязка к OpenAPI

Фоновая очередь и запись событий; HTTP-маршруты приёма относятся к задаче 53.

## Зависимости и проверка

Предшествующие задачи: №4, №54.

Проверить положительный сценарий, ошибки валидации и доступа, а также сохранение/чтение данных там, где это применимо. Для HTTP-маршрутов сверить фактические тела и статусы с OpenAPI и выполнить `./gradlew test openApiValidate build`.
