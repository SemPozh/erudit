# Задача 93. Разделение OpenAPI и проверка контрактов

- **Лабораторная:** ЛР2
- **Исполнитель:** Илья
- **Сервис:** `platform/api`
- **Статус:** done — service-owned OpenAPI и contract gate настроены
- **Оценка изменений:** до 1700 строк, generated-код не считается
- **Зависит от:** 74–90

## Цель

Разделить монолитную спецификацию по владельцам и сохранить внешний API.

## Что сделать

1. Перенести paths/schemas в service-owned OpenAPI files.
2. Генерировать server interfaces и Feign clients из соответствующих контрактов.
3. Добавить diff-проверку совместимости внешних paths ЛР1.
4. Удалить auth security schemes и добавить working examples/demo prerequisites.

## Критерии готовности

- [x] Каждая спецификация валидируется отдельно.
- [x] Нет одинаковых внешних path/operationId в двух сервисах.
- [x] Gateway routing включает все внешние операции и исключает internal.

## Реализация

- `verifyServiceContracts` проверяет уникальность external path/operationId и отсутствие auth schemes.
- Server interfaces продолжают генерироваться из service-owned specifications; internal Feign DTO централизованы.
- Gateway paths синхронизированы с фактическими User/Quiz контрактами, internal paths не маршрутизируются.

## Общие ограничения ЛР2

- Авторизацию, JWT, Spring Security и проверки ролей не добавлять.
- Реальные email, push и SMS не отправлять; это относится к ЛР4.
- Не обращаться напрямую к БД другого сервиса и не переиспользовать его Entity.
- Внешние HTTP DTO задаются OpenAPI; generated-код не коммитится.
- Если фактический diff достигает 1800 строк, остаток вынести в новую задачу до PR.
