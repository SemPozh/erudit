## Цель

Реализовать второй обязательный реактивный сервис на Reactor и Spring Data JDBC.

## Что сделать

1. Перенести preferences, templates, inbox, unread/read operations и paged lists.
2. Выполнять JDBC на выделенном boundedElastic scheduler с ограниченным пулом.
3. Добавить internal API постановки уведомления и массовой постановки.
4. Все адресаты и delivery records локальны; внешних SDK и сетевой отправки нет.

## Критерии готовности

- [ ] Тест доказывает отсутствие JDBC на event loop.
- [ ] Все notification paths доступны через Gateway без Authorization.
- [ ] PostgreSQL Testcontainers покрывает CRUD, pagination и read transitions.

## Общие ограничения ЛР2

- Авторизацию, JWT, Spring Security и проверки ролей не добавлять.
- Реальные email, push и SMS не отправлять; это относится к ЛР4.
- Не обращаться напрямую к БД другого сервиса и не переиспользовать его Entity.
- Внешние HTTP DTO задаются OpenAPI; generated-код не коммитится.
- Если фактический diff достигает 1800 строк, остаток вынести в новую задачу до PR.
