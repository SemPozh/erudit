# Задача 105. Пользовательские и контентные domain events

- **Лабораторная:** ЛР4
- **Исполнитель:** Семен
- **Сервис:** `erudit-user / erudit-content`
- **Статус:** todo
- **Оценка изменений:** 900–1500 строк
- **Зависит от:** 102

## Цель

Публиковать значимые изменения пользователей и контента через transactional Outbox,
чтобы подписчики не опрашивали сервисы и не зависели от синхронных команд.

## Что сделать

1. User публикует `UserCreated`, `UserBlocked`, `UserDeleted` без password/hash.
2. Content публикует `ContentCreated`, `ContentPublished`, `ContentArchived`,
   `ContentModerationRequested` с минимальным payload.
3. Записывать бизнес-данные и Outbox в одной транзакции.
4. Добавить schema version, partition key по aggregate ID и correlation/actor IDs.
5. Перевести подходящие fire-and-forget Feign вызовы на события согласно задаче 100.
6. Добавить contract и Kafka/PostgreSQL integration tests, включая duplicate/retry.

## Критерии готовности

- [ ] На один commit создаётся ровно одно логическое событие.
- [ ] Rollback не публикует событие; временная недоступность Kafka не теряет его.
- [ ] Payload не содержит пароль, hash, JWT и лишние персональные данные.
- [ ] Старые синхронные команды удалены там, где утверждён async flow.
- [ ] Consumers могут независимо обновляться по правилам совместимости.

## API и проверка

Публичные HTTP-контракты сохраняются, кроме документированных изменений задачи 104.
Проверить register/block/content lifecycle и содержимое Kafka records.
