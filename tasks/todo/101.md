# Задача 101. Kafka-кластер из трёх брокеров

- **Лабораторная:** ЛР4
- **Исполнитель:** Илья
- **Сервис:** `platform`
- **Статус:** todo
- **Оценка изменений:** 700–1200 строк
- **Зависит от:** 100

## Цель

Добавить воспроизводимый Kafka KRaft cluster из трёх брокеров с репликацией и
без публикации брокерских портов наружу по умолчанию.

## Что сделать

1. Добавить в Compose три Kafka broker/controller, persistent volumes,
   healthchecks, resource limits и внутреннюю сеть.
2. Создать declarative init для топиков ЛР4: domain events, notifications,
   notification retry/DLT и file lifecycle.
3. Для рабочих топиков установить replication factor `3`, `min.insync.replicas=2`
   и минимум три partition; DLT может иметь отдельную retention policy.
4. Настроить producer `acks=all`, idempotence и безопасные timeouts через Config Server.
5. Добавить debug profile с Kafka UI только на loopback.
6. Написать smoke-скрипт: проверить ISR, лидеров, запись/чтение и продолжение работы
   после остановки одного брокера.

## Критерии готовности

- [ ] Все три брокера healthy, топики создаются идемпотентно.
- [ ] У каждой partition три replica и не менее двух ISR в штатном режиме.
- [ ] При падении одного брокера producer/consumer продолжают работать.
- [ ] Из внешней сети доступны только Gateway и opt-in debug UI.
- [ ] `docker compose up --build` остаётся повторяемым.

## API и проверка

Собственного HTTP API нет. Проверка: Compose validation, smoke cluster test,
restart одного broker и подтверждение отсутствия потери acknowledged message.
