# Задача 103. Микросервис файлов и объектное хранилище

- **Лабораторная:** ЛР4
- **Исполнитель:** Семен
- **Сервис:** `erudit-file`
- **Статус:** todo
- **Оценка изменений:** 1400–2000 строк
- **Зависит от:** 100, 101, 102

## Цель

Добавить отдельный сервис загрузки и получения файлов с метаданными, проверкой
владельца и хранением бинарных данных вне БД.

## Что сделать

1. Создать Spring Boot module `erudit-file`, отдельную PostgreSQL schema и MinIO
   в Compose; наружу сервис доступен только через Gateway.
2. Реализовать порты `FileMetadataRepository`, `ObjectStorage`, `EventPublisher`
   и use cases upload/download/delete без зависимости domain/application от Spring.
3. Добавить `POST /api/v1/files` multipart, `GET /api/v1/files/{id}` streaming,
   `GET /api/v1/files/{id}/metadata`, `DELETE /api/v1/files/{id}`.
4. Ограничить размер, MIME allowlist, нормализовать имя, считать SHA-256;
   владелец берётся только из доверенного `X-User-Id`.
5. Публиковать `FileStored` и `FileDeleted` через Outbox.
6. Добавить OpenAPI, Gateway route, Config/Eureka, Docker image и Testcontainers tests.

## Критерии готовности

- [ ] Авторизованный пользователь загружает и скачивает файл без чтения его целиком в heap.
- [ ] Чужой файл нельзя удалить; отсутствующий файл даёт 404, неверный тип/размер — 400/413.
- [ ] Metadata и object согласованы при ошибках и повторных запросах.
- [ ] Внешние порты MinIO/PostgreSQL/file-service не опубликованы.
- [ ] Покрытие модуля не ниже 80%.

## API и проверка

Все четыре операции описать в `erudit-file/openapi.yaml`, добавить Bearer security
и E2E через Gateway с реальным PostgreSQL + MinIO + Kafka Testcontainers.
