# Задача 108. Доставка уведомлений, retry и DLT

- **Лабораторная:** ЛР4
- **Исполнитель:** Семен
- **Сервис:** `erudit-notificator`
- **Статус:** todo
- **Оценка изменений:** 800–1500 строк
- **Зависит от:** 107

## Цель

Добавить управляемую доставку уведомлений через Kafka с несколькими каналами,
повторами и наблюдаемым terminal failure.

## Что сделать

1. Реализовать Clean Architecture ports для email/push/in-app delivery.
2. Оставить безопасные local adapters по умолчанию; реальные SMTP/push adapters
   включать только отдельным profile и environment secrets.
3. Consumer `notifications.delivery` обновляет статусы `PENDING/SENT/FAILED/DLT`.
4. Настроить exponential retry, лимит попыток и публикацию в DLT с причиной.
5. Добавить admin replay операции для DLT с идемпотентностью и аудитом роли.
6. Добавить metrics: lag, sent/failed, retry count, DLT size и structured logs.

## Критерии готовности

- [ ] Успешная доставка завершается `SENT` ровно один раз.
- [ ] Временная ошибка повторяется, постоянная попадает в DLT.
- [ ] Replay доступен только MODERATOR/SUPERVISOR и не дублирует отправку.
- [ ] Секреты и содержимое сообщений не попадают в логи.
- [ ] Kafka Testcontainers tests покрывают retry и DLT.

## API и проверка

Добавить `POST /api/v1/admin/notifications/dlt/{eventId}/replay` с 202/404/409 и
Bearer role rules. Основная доставка остаётся асинхронной без публичной create-ручки.
