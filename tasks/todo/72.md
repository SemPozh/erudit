# Задача 72. Технический starter: ошибки, request ID и observability

- **Лабораторная:** ЛР2
- **Исполнитель:** Илья
- **Сервис:** `platform`
- **Статус:** todo
- **Оценка изменений:** до 1500 строк, generated-код не считается
- **Зависит от:** 67

## Цель

Вынести только технические соглашения, одинаковые для всех сервисов.

## Что сделать

1. Добавить общий формат ошибки, обработку validation/malformed JSON и request ID filter.
2. Настроить JSON logs, trace propagation, Actuator, Prometheus и readiness/liveness.
3. Не включать Entity, бизнес DTO, репозитории или бизнес exceptions в общий модуль.
4. Проверить совместимость starter с MVC и WebFlux.

## Критерии готовности

- [ ] MVC и WebFlux тестовые приложения возвращают одинаковый формат ошибок.
- [ ] Request ID проходит в ответ и MDC/Reactor Context.
- [ ] Starter не тянет JPA/JDBC/R2DBC транзитивно.

## Общие ограничения ЛР2

- Авторизацию, JWT, Spring Security и проверки ролей не добавлять.
- Реальные email, push и SMS не отправлять; это относится к ЛР4.
- Не обращаться напрямую к БД другого сервиса и не переиспользовать его Entity.
- Внешние HTTP DTO задаются OpenAPI; generated-код не коммитится.
- Если фактический diff достигает 1800 строк, остаток вынести в новую задачу до PR.

## Проверка

- Unit-тесты для новой логики; integration/Testcontainers для данных и HTTP.
- Запустить проверки изменённых модулей и корневые `./gradlew test openApiValidate build`.
- Проверить запуск изменённых контейнеров и соответствие `docs/lab2-architecture.md`.
