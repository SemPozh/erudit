# Задача 112. Приёмочные E2E, отказоустойчивость и документация ЛР4

- **Лабораторная:** ЛР4
- **Исполнитель:** Илья
- **Сервис:** `all services`
- **Статус:** todo
- **Оценка изменений:** 900–1600 строк
- **Зависит от:** 101–111

## Цель

Доказать, что вся ЛР4 запускается одной командой, события не теряются, файловый
сервис и уведомления доступны через Gateway, а все сервисы соблюдают Clean Architecture.

## Что сделать

1. Добавить системный E2E: login → upload file → create/publish content → domain event →
   notification → list/read notification → download/delete file.
2. Добавить payment и quiz сценарии, создающие разные notification topics/templates.
3. Проверить duplicate delivery, Kafka outage/recovery, падение одного из трёх brokers,
   consumer restart, retry и DLT replay.
4. Проверить security: 401/403, роли, ownership файла, отсутствие внешних портов сервисов.
5. Добавить CI jobs с Kafka/PostgreSQL/MinIO Testcontainers и coverage gate >80%.
6. Обновить README, Swagger runbook, topic catalog, Clean Architecture diagrams,
   команды диагностики/reset и отчёт фактических E2E результатов.

## Критерии готовности

- [ ] Fresh `docker compose up --build` приводит окружение в healthy.
- [ ] Три Kafka broker имеют RF=3/min ISR=2; остановка одного не ломает сценарий.
- [ ] Все публичные операции доступны только через Gateway и документированы.
- [ ] `./gradlew clean build` и coverage gate проходят для всех модулей.
- [ ] Документированный E2E воспроизводится на чистых volumes.

## API и проверка

Новых бизнес-маршрутов нет. Результат — автоматический smoke/E2E script, CI gate,
Swagger verification и acceptance matrix по каждому требованию ЛР4.
