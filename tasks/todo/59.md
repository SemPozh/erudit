# Задача 59. Валидация тела жалобы на контент

- **Исполнитель:** Вячеслав
- **Домен (будущий микросервис):** erudit-content
- **Статус:** todo
- **Связанные требования:** REQ 4.11
- **Зависит от:** каркас ручки жалобы (готов); завершение задачи 20 не требуется

## Контекст

В `ContentReportController` уже есть `POST /api/v1/content/{id}/report`. Контракт
ручки задаётся в `src/main/resources/static/openapi.yaml`, а Java-интерфейс
`ContentReportsApi` генерируется при сборке. Пользователь
отправляет текст жалобы в JSON. Контроллер должен отклонять пустой или слишком
длинный текст до вызова сервиса. В проекте уже есть Spring Validation и общий
обработчик `MethodArgumentNotValidException`, который возвращает HTTP 400 в
формате `ApiResponse`.

## Что сделать

1. Дополнить **один DTO-класс** `ContentReportRequest` в пакете
   `com.erudit.content`. Поле `reason` типа `String`:
   обязательное, не состоящее только из пробелов, длина исходной строки от 10 до 500 символов.
   Использовать стандартные аннотации `@NotBlank` и `@Size(min = 10, max = 500)`
   из `jakarta.validation.constraints`. Текст из запроса не должен попадать в
   path-параметр `id`.
2. Интерфейс уже принимает DTO через `@Valid @RequestBody`, а контроллер передаёт
   `request.reason()` в сервис жалоб. Проверить это поведение и добавить в схему
   `ContentReportRequest.reason` ограничения `minLength: 10`, `maxLength: 500`,
   чтобы Swagger показывал те же правила. Бизнес-логику, схему БД и общий
   обработчик ошибок не менять.
3. Дополнить тест контроллера случаями ниже. Можно добавить методы в существующий
   тестовый класс; отдельная тестовая инфраструктура не нужна.

Пример корректного запроса:

```http
POST /api/v1/content/123/report
Content-Type: application/json

{"reason":"В материале есть фактическая ошибка"}
```

## Критерии готовности

- [ ] Корректный `reason` (10–500 символов) проходит к сервису жалоб.
- [ ] Пустая строка, пробелы и строка короче 10 символов дают HTTP 400.
- [ ] Строка длиннее 500 символов даёт HTTP 400.
- [ ] Ошибки возвращаются в общем формате `ApiResponse` с кодом
      `VALIDATION_ERROR`; сервис жалоб при ошибке не вызывается.
- [ ] Тесты проходят через `./gradlew test`.
