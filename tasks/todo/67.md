# Задача 67. Каркас Gradle multi-project для ЛР2

- **Лабораторная:** ЛР2
- **Исполнитель:** Илья
- **Сервис:** `platform`
- **Статус:** todo
- **Оценка изменений:** до 1200 строк, generated-код не считается
- **Зависит от:** нет

## Цель

Подготовить структуру репозитория, в которой каждый сервис собирается и запускается независимо, не ломая текущий монолит до завершения миграции.

## Что сделать

1. Создать каталоги `infrastructure/*`, `services/*` и корневое подключение Gradle subprojects.
2. Зафиксировать совместимые Spring Boot/Spring Cloud BOM и Java toolchain; зависимости каждого модуля объявлять локально.
3. Добавить соглашения `bootJar`, тестов, JaCoCo и OpenAPI без общей библиотеки бизнес-моделей.
4. Сохранить временную сборку legacy-модуля до задачи 99.

## Критерии готовности

- [ ] Корневые `gradlew build` и сборка отдельного пустого сервиса проходят.
- [ ] Ни один модуль не зависит от исходников другого модуля напрямую.
- [ ] Документация объясняет добавление нового сервиса и лимит PR 2000 строк.

## Общие ограничения ЛР2

- Авторизацию, JWT, Spring Security и проверки ролей не добавлять.
- Реальные email, push и SMS не отправлять; это относится к ЛР4.
- Не обращаться напрямую к БД другого сервиса и не переиспользовать его Entity.
- Внешние HTTP DTO задаются OpenAPI; generated-код не коммитится.
- Если фактический diff достигает 1800 строк, остаток вынести в новую задачу до PR.

## Проверка

- Unit-тесты для новой логики; integration/Testcontainers для данных и HTTP.
- Запустить проверки изменённых модулей и корневые `./gradlew test openApiValidate build`.
- Проверить запуск изменённых контейнеров и соответствие `docs/lab2-architecture.md`.
