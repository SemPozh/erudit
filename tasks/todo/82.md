## Цель

Реализовать обязательный реактивный сервис Reactor + R2DBC.

## Что сделать

1. Создать WebFlux API одиночного и batch ingestion.
2. Хранить receipt/idempotency в отдельном PostgreSQL через R2DBC migrations.
3. Использовать Reactor end-to-end, backpressure и bounded batch до 100.
4. Публиковать принятые события во внутренний Reactor pipeline; без Kafka до ЛР4.

## Критерии готовности

- [ ] Event loop не содержит блокирующих repository/Feign вызовов.
- [ ] Повтор eventId не создаёт вторую обработку.
- [ ] R2DBC Testcontainers tests покрывают batch, concurrency, validation и backpressure.

## Общие ограничения ЛР2

- Авторизацию, JWT, Spring Security и проверки ролей не добавлять.
- Реальные email, push и SMS не отправлять; это относится к ЛР4.
- Не обращаться напрямую к БД другого сервиса и не переиспользовать его Entity.
