# Задача 100. Финальная приёмка и демонстрационный runbook ЛР2

- **Лабораторная:** ЛР2
- **Исполнитель:** Семен
- **Сервис:** `documentation/acceptance`
- **Статус:** todo
- **Оценка изменений:** до 1200 строк, generated-код не считается
- **Зависит от:** 96, 97, 98, 99

## Цель

Провести полную приёмку требований ЛР2 и подготовить воспроизводимую демонстрацию.

## Что сделать

1. Составить матрицу Eureka, Config Server, Gateway, Feign, Circuit Breaker, Reactor+R2DBC и Reactor+JDBC со ссылками на код/тесты.
2. Зафиксировать обоснование сервисных границ, транзакций и scheduler isolation.
3. Описать запуск, Swagger, demo reset, сбой зависимости и восстановление Circuit Breaker.
4. Записать результаты финального E2E и список всех доступных endpoints.

## Критерии готовности

- [ ] Все приложения видны в Eureka и читают конфигурацию Config Server.
- [ ] Swagger и E2E проходят на чистом окружении; ни одна ручка не возвращает 401.
- [ ] Подтверждено отсутствие реальных уведомлений и авторизации.
- [ ] `test`, OpenAPI validation, coverage, build и Compose smoke проходят в CI.

## Общие ограничения ЛР2

- Авторизацию, JWT, Spring Security и проверки ролей не добавлять.
- Реальные email, push и SMS не отправлять; это относится к ЛР4.
- Не обращаться напрямую к БД другого сервиса и не переиспользовать его Entity.
- Внешние HTTP DTO задаются OpenAPI; generated-код не коммитится.
- Если фактический diff достигает 1800 строк, остаток вынести в новую задачу до PR.

## Проверка

- Unit-тесты для новой логики; integration/Testcontainers для данных и HTTP.
- Запустить проверки изменённых модулей и корневые `./gradlew test openApiValidate build`.
- Проверить запуск изменённых контейнеров и соответствие `docs/lab2-architecture.md`.
