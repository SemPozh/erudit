# Задача 111. Clean Architecture: payment, AI, event-receiver и gateway

- **Лабораторная:** ЛР4
- **Исполнитель:** Илья
- **Сервис:** `erudit-payment / erudit-ai-platform / erudit-event-receiver / gateway`
- **Статус:** todo
- **Оценка изменений:** 1300–2000 строк
- **Зависит от:** 106

## Цель

Завершить Clean Architecture во всех оставшихся бизнес-сервисах и не смешивать
security/routing infrastructure Gateway с доменной логикой.

## Что сделать

1. Выделить domain/application/ports/adapters в payment, AI и event-receiver.
2. Изолировать webhook/Kafka/R2DBC/ClickHouse/AI provider implementations в adapters.
3. В Gateway разделить security, routing, contract catalog и observability ports;
   не переносить доменную авторизацию из владельцев ресурсов.
4. Оставить Config/Eureka servers инфраструктурными приложениями без фиктивного domain.
5. Добавить общерепозиторные ArchUnit rules для каждого микросервиса.
6. Обновить ADR с обоснованными исключениями и запретить framework types в use cases.

## Критерии готовности

- [ ] Все бизнес-микросервисы соответствуют одинаковому dependency rule.
- [ ] Reactive цепочки не содержат blocking JDBC/file calls на event loop.
- [ ] Payment idempotency и AI circuit breaker сохранены.
- [ ] Gateway продолжает проверять JWT и закрывать прямой spoofing headers.
- [ ] Покрытие модулей не ниже 80%.

## API и проверка

Новых маршрутов нет, кроме status API из задачи 106. Проверить ArchUnit,
BlockHound/reactive tests, security tests и полный OpenAPI baseline.
