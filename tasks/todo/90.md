# Задача 90. Admin service: фасад и аудит

- **Лабораторная:** ЛР2
- **Исполнитель:** Дестини
- **Сервис:** `erudit-admin`
- **Статус:** todo
- **Оценка изменений:** до 1900 строк, generated-код не считается
- **Зависит от:** 74, 78, 84, 86, 91

## Цель

Извлечь административный API как оркестратор без доступа к чужим базам.

## Что сделать

1. Перенести admin audit в собственный PostgreSQL через Spring Data JPA/JDBC.
2. Реализовать users/block, moderation/reports, notification send-many и payment views через Feign.
3. Сохранять audit результата и request ID локально.
4. Не проверять роль ADMIN в ЛР2; описание Swagger явно указывает учебный режим.

## Критерии готовности

- [ ] В admin module нет repositories/Entity чужих доменов.
- [ ] Partial failure даёт структурированную ошибку и audit status.
- [ ] Интеграционные тесты используют stub services и собственный PostgreSQL Testcontainer.

## Общие ограничения ЛР2

- Авторизацию, JWT, Spring Security и проверки ролей не добавлять.
- Реальные email, push и SMS не отправлять; это относится к ЛР4.
- Не обращаться напрямую к БД другого сервиса и не переиспользовать его Entity.
- Внешние HTTP DTO задаются OpenAPI; generated-код не коммитится.
- Если фактический diff достигает 1800 строк, остаток вынести в новую задачу до PR.
