# Задача 104. Миграция медиа контента на erudit-file

- **Лабораторная:** ЛР4
- **Исполнитель:** Семен
- **Сервис:** `erudit-content / erudit-file`
- **Статус:** todo
- **Оценка изменений:** 700–1300 строк
- **Зависит от:** 103

## Цель

Убрать локальное файловое хранилище content-service и связать контент с файлами
через file ID и события жизненного цикла.

## Что сделать

1. Заменить `mediaUrl`/локальный volume на nullable `fileId` и миграцию данных.
2. Для немедленной проверки файла использовать Feign query к erudit-file;
   lifecycle `FileDeleted` обрабатывать асинхронно через Kafka.
3. При удалении файла идемпотентно очищать/помечать media link у контента.
4. Запретить привязку чужого, удалённого или неподходящего MIME файла.
5. Обновить OpenAPI ContentRequest/Response, Swagger examples и demo fixtures.
6. Удалить устаревший content media volume только после миграционного сценария.

## Критерии готовности

- [ ] Контент создаётся с корректным `fileId` и возвращает пригодную download-ссылку.
- [ ] Чужой/удалённый файл отклоняется человекочитаемой ошибкой.
- [ ] `FileDeleted` не ломает consumer при повторной доставке.
- [ ] Старое локальное storage больше не используется.
- [ ] Контрактные и интеграционные тесты проходят.

## API и проверка

Изменить `POST/PUT/GET /api/v1/content`. Проверить сценарий upload → create content →
download → delete file → content without media через Gateway.
