# Задача 102. Event SDK, Outbox и Inbox

- **Лабораторная:** ЛР4
- **Исполнитель:** Илья
- **Сервис:** `platform:erudit-integration`
- **Статус:** todo
- **Оценка изменений:** 900–1600 строк
- **Зависит от:** 100, 101

## Цель

Дать сервисам единый технический механизм надёжной публикации и идемпотентного
потребления событий без переноса доменных моделей в shared module.

## Что сделать

1. Реализовать общий event envelope, headers и JSON serialization/version checks.
2. Добавить локальные Outbox migrations/API: запись события в одной транзакции с
   бизнес-изменением, polling publisher, retry и отметка публикации.
3. Добавить Inbox/Deduplication API для consumers с уникальным `eventId`.
4. Настроить correlation/request ID propagation и безопасное логирование без PII.
5. Предоставить test fixtures для Kafka Testcontainers и проверки duplicate delivery.
6. Не добавлять shared Entity или бизнес DTO; payload принадлежит producer-сервису.

## Критерии готовности

- [ ] DB rollback не оставляет событие, commit гарантирует eventual publish.
- [ ] Повторная доставка не повторяет бизнес-эффект.
- [ ] Неуспешная публикация повторяется без блокирования HTTP-потока.
- [ ] Версия и неизвестный тип события обрабатываются контролируемо.
- [ ] SDK покрыт unit и PostgreSQL/Kafka integration tests.

## API и проверка

Новых публичных маршрутов нет. Проверить `./gradlew :platform:erudit-integration:test`
и интеграционный сценарий PostgreSQL + Kafka Testcontainers.
