- **Зависит от:** 67

## Цель

Добавить Spring Cloud Config Server и вынести в него общие и сервисные настройки ЛР2.

## Что сделать

1. Создать Config Server с native-профилем для Docker и тестов.
2. Создать `config-repository` с общими timeout, pagination, Actuator, Eureka и service-specific настройками.
3. Секреты и пароли оставить placeholders переменных окружения, не коммитить реальные значения.
4. Добавить healthcheck и fail-fast/retry клиентов при старте.

## Критерии готовности

- [ ] Config Server отдаёт конфигурацию каждого приложения по имени и профилю.
- [ ] Изменение значения в config repository применяется после перезапуска сервиса.
- [ ] Тест проверяет выдачу конфигурации и отсутствие секретов в Git.

## Общие ограничения ЛР2

- Авторизацию, JWT, Spring Security и проверки ролей не добавлять.
- Реальные email, push и SMS не отправлять; это относится к ЛР4.
- Не обращаться напрямую к БД другого сервиса и не переиспользовать его Entity.
- Внешние HTTP DTO задаются OpenAPI; generated-код не коммитится.
- Если фактический diff достигает 1800 строк, остаток вынести в новую задачу до PR.

- Unit-тесты для новой логики; integration/Testcontainers для данных и HTTP.
- Запустить проверки изменённых модулей и корневые `./gradlew test openApiValidate build`.
- Проверить запуск изменённых контейнеров и соответствие `docs/lab2-architecture.md`.
