# Задача 110. Clean Architecture: content, file и notificator

- **Лабораторная:** ЛР4
- **Исполнитель:** Семен
- **Сервис:** `erudit-content / erudit-file / erudit-notificator`
- **Статус:** todo
- **Оценка изменений:** 1200–2000 строк
- **Зависит от:** 103, 104, 107, 108

## Цель

Обеспечить Clean Architecture в сервисах контента, файлов и уведомлений после
добавления Kafka и object storage adapters.

## Что сделать

1. Выделить независимые domain models и application use cases/ports.
2. Разнести web/Kafka входы и JDBC/MinIO/Kafka/Feign выходы по adapters.
3. Исключить зависимости application от servlet request, Kafka record, JdbcClient,
   MinIO SDK и generated DTO.
4. Централизовать mapping, transaction boundary и обработку ошибок на границах.
5. Добавить architecture tests для запрещённых направлений зависимостей.
6. Сохранить streaming/backpressure для файлов и идемпотентность consumers.

## Критерии готовности

- [ ] Domain/application компилируются без infrastructure framework imports.
- [ ] HTTP и Kafka используют одни и те же application use cases.
- [ ] Замена local delivery/MinIO/Kafka возможна через другой adapter.
- [ ] Интеграционные и E2E тесты остаются зелёными.
- [ ] Покрытие каждого сервиса не ниже 80%.

## API и проверка

Контракты задач 103, 104 и 108 не менять. Проверить ArchUnit, unit use cases,
PostgreSQL/MinIO/Kafka Testcontainers и Gateway E2E.
