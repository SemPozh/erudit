# Задача 28. Источники предпочтений для подбора программы

- **Исполнитель:** Илья
- **Домен (будущий микросервис):** erudit-ai-platform
- **Статус:** todo
- **Связанные требования:** REQ 3.5

## Описание

Собирать предпочтения пользователя для подбора программы из трёх источников: настройки
профиля (любимые тематики), выбор при онбординге/входном тесте, поведенческие сигналы из
аналитики (с каким контентом пользователь реально взаимодействует).

## Что должно получиться

- Агрегация предпочтений из указанных источников.
- Учёт предпочтений в алгоритме подбора.
- Приоритизация источников/конфликтов.

## Критерии готовности

- [ ] Предпочтения собираются из всех трёх источников.
- [ ] Учитываются в построении программы.
- [ ] Покрыто тестами.

## Привязка к OpenAPI

Ограничения времени и формата применяются в программе обучения; отдельного HTTP-маршрута нет.

## Зависимости и проверка

Предшествующие задачи: №12, №27, №55.

Проверить положительный сценарий, ошибки валидации и доступа, а также сохранение/чтение данных там, где это применимо. Для HTTP-маршрутов сверить фактические тела и статусы с OpenAPI и выполнить `./gradlew test openApiValidate build`.
