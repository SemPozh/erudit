# Задача 73. Базовый Docker Compose для инфраструктуры ЛР2

- **Лабораторная:** ЛР2
- **Исполнитель:** Илья
- **Сервис:** `platform`
- **Статус:** todo
- **Оценка изменений:** до 1100 строк, generated-код не считается
- **Зависит от:** 68, 69, 70

## Цель

Подготовить Compose-каркас, на который будут добавляться бизнес-сервисы.

## Что сделать

1. Добавить Config Server, Eureka, Gateway и сети `edge`/`internal`.
2. Настроить health-based startup, restart policy, profiles и именованные volumes.
3. Не публиковать наружу порты бизнес-сервисов в финальном профиле; для отладки использовать отдельный profile.
4. Добавить `.env.example` без секретов.

## Критерии готовности

- [ ] Инфраструктура стартует одной командой и достигает healthy.
- [ ] Gateway ждёт Config/Eureka через healthcheck, а не sleep.
- [ ] После рестарта registry и gateway восстанавливаются автоматически.

## Общие ограничения ЛР2

- Авторизацию, JWT, Spring Security и проверки ролей не добавлять.
- Реальные email, push и SMS не отправлять; это относится к ЛР4.
- Не обращаться напрямую к БД другого сервиса и не переиспользовать его Entity.
- Внешние HTTP DTO задаются OpenAPI; generated-код не коммитится.
- Если фактический diff достигает 1800 строк, остаток вынести в новую задачу до PR.

## Проверка

- Unit-тесты для новой логики; integration/Testcontainers для данных и HTTP.
- Запустить проверки изменённых модулей и корневые `./gradlew test openApiValidate build`.
- Проверить запуск изменённых контейнеров и соответствие `docs/lab2-architecture.md`.
