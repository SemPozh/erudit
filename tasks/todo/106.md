# Задача 106. События quiz, payment и AI

- **Лабораторная:** ЛР4
- **Исполнитель:** Илья
- **Сервис:** `erudit-quiz / erudit-payment / erudit-ai-platform`
- **Статус:** todo
- **Оценка изменений:** 1100–1900 строк
- **Зависит от:** 102

## Цель

Перевести асинхронные результаты викторин, платежей и генерации AI на Kafka,
сохранив HTTP только для запросов с немедленным ответом.

## Что сделать

1. Quiz публикует `QuizCompleted`, `AssessmentCompleted`, `CompetitionFinished`.
2. Payment публикует `PaymentSucceeded`, `PaymentFailed`, `SubscriptionChanged`;
   webhook сначала фиксируется идемпотентно, затем событие выходит из Outbox.
3. AI принимает `QuizGenerationRequested` и публикует `QuizGenerationCompleted/Failed`;
   добавить status query для длительной операции.
4. Использовать aggregate ID как Kafka key, Inbox для consumers, retry/DLT для
   невосстановимых ошибок и correlation ID по всей цепочке.
5. Удалить заменённые fire-and-forget Feign calls, не трогая query interactions.
6. Добавить тесты порядка, дублей, rollback и временной недоступности broker.

## Критерии готовности

- [ ] Платёжный webhook не создаёт двойной эффект.
- [ ] AI request не удерживает HTTP соединение до генерации.
- [ ] Quiz events сохраняют порядок в пределах aggregate.
- [ ] Ошибки попадают в retry, затем DLT с диагностическими headers.
- [ ] Testcontainers tests воспроизводят полный поток.

## API и проверка

При необходимости добавить `POST /api/v1/ai/quiz-generations` (202 + operation ID)
и `GET /api/v1/ai/quiz-generations/{id}`; остальные публичные контракты совместимы.
