# Задача 107. Kafka intake для уведомлений

- **Лабораторная:** ЛР4
- **Исполнитель:** Семен
- **Сервис:** `erudit-notificator`
- **Статус:** todo
- **Оценка изменений:** 1000–1700 строк
- **Зависит от:** 101, 102, 105, 106

## Цель

Формировать уведомления из доменных событий без синхронных вызовов notificator.

## Что сделать

1. Подписать notificator на user/content/quiz/payment/AI topics.
2. Реализовать mapping событий в шаблоны минимум для трёх случаев: результат quiz,
   успешный платёж и публикация/модерация контента.
3. Учитывать настройки пользователя и канал; хранить notification и eventId атомарно.
4. Применить Inbox, чтобы duplicate event не создавал повторное уведомление.
5. Разделить топики `notifications.requested`, `notifications.delivery`,
   `notifications.retry`, `notifications.dlt` с RF=3.
6. Обновить list/read API и добавить integration tests с Kafka/PostgreSQL.

## Критерии готовности

- [ ] Не менее трёх типов событий создают корректные уведомления.
- [ ] Дубликат события не создаёт вторую запись.
- [ ] Отключённый пользователем канал не планируется к доставке.
- [ ] Неизвестная версия события обрабатывается без остановки partition.
- [ ] HTTP producers больше не вызывают notificator напрямую.

## API и проверка

Сохраняются `GET /api/v1/notifications` и операция read; создание происходит только
из Kafka. Проверить три producer flow через Gateway и появление уведомлений пользователя.
