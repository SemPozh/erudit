## Цель

Создать единую внешнюю точку входа на Spring Cloud Gateway с маршрутами по service ID.

## Что сделать

1. Перенести внешние `/api/v1/**` маршруты без изменения путей.
2. Добавить CORS, ограничения тела, request/response logging и генерацию/проброс `X-Request-ID`.
3. Пробрасывать необязательный `X-User-Id`; не добавлять JWT, SecurityFilterChain и проверки ролей.
4. Закрыть наружную маршрутизацию `/internal/v1/**`, Eureka и Config Server.

## Критерии готовности

- [ ] Маршруты разрешаются через Eureka, а не фиксированные host:port.
- [ ] Запрос без Authorization достигает целевого сервиса.
- [ ] Неизвестный маршрут даёт структурированный 404, недоступный сервис — структурированный 503.

## Общие ограничения ЛР2

- Авторизацию, JWT, Spring Security и проверки ролей не добавлять.
- Реальные email, push и SMS не отправлять; это относится к ЛР4.
- Не обращаться напрямую к БД другого сервиса и не переиспользовать его Entity.
- Внешние HTTP DTO задаются OpenAPI; generated-код не коммитится.
- Если фактический diff достигает 1800 строк, остаток вынести в новую задачу до PR.
