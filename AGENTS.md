# Инструкции разработки ERUDIT

Перед изменением кода прочитайте `docs/development-rules.md` и применяйте раздел
«Обязательные правила текущего этапа».

- Работайте в feature-ветке от актуального `main`; коммиты оформляйте по Conventional Commits.
- Для ЛР 2 соблюдайте границы из `docs/lab2-architecture.md`; сервис не читает чужую БД и не импортирует чужие Entity.
- Авторизация запрещена до ЛР 3; реальные email/push/SMS запрещены до ЛР 4.
- Один PR задачи ЛР 2 не должен превышать 2000 изменённых строк без generated-кода.
- Поддерживайте единый OpenAPI-контракт и реализацию контроллеров через сгенерированные API-интерфейсы.
- Разделяйте HTTP DTO, доменные модели, сервисы и репозитории. Все изменения схемы делайте Flyway-миграциями.
- Для списков обязательны пагинация и лимит не более 50 элементов. Параметры сортировки должны использовать allowlist.
- Новая бизнес-логика требует unit-тестов, работа с БД — интеграционных тестов PostgreSQL через Testcontainers.
- Перед PR выполните `./gradlew test openApiValidate build`; приложение должно запускаться через Docker Compose.
- Не начинайте требования будущих этапов декомпозиции без соответствующей задачи, но не принимайте решения, которые им препятствуют.
