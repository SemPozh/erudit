# Архитектура и соответствие требованиям

## Общая схема

Приложение является модульным монолитом Spring Boot. Модули `user`, `content`,
`quiz`, `assessment`, `program`, `competition`, `rating`, `notification`,
`payment`, `events` и `admin` разделяют контроллеры, сервисы и репозитории,
но собираются и развёртываются одним приложением.

PostgreSQL хранит транзакционные данные. ClickHouse хранит поток аналитических
событий. Структура PostgreSQL создаётся только Flyway-миграциями из
`src/main/resources/db/migration`.

## Связи данных

- **One to many / many to one:** категория содержит много материалов; пользователь
  имеет много refresh-токенов, попыток, платежей и уведомлений.
- **Many to many:** `user_favorite_categories` связывает пользователей и категории.
- **Many to many с дополнительным полем:** `competition_participants` связывает
  соревнования и пользователей и хранит `joined_at`.
- Дополнительные уникальные связи и внешние ключи заданы в миграциях. Enum-значения
  сохраняются строками (`VARCHAR` и `EnumType.STRING`).

Эта схема является документом для согласования с преподавателем. Изменения схемы
после согласования следует оформлять новой Flyway-миграцией; уже применённые
миграции не редактируются.

## Пагинация

- Обычные списки принимают `page` и `size`; `size` ограничен диапазоном 1–50.
- Каталог `GET /api/v1/content` возвращает общее количество в заголовке
  `X-Total-Count`.
- Персональная лента `GET /api/v1/content/feed` реализует бесконечную прокрутку без
  запроса `COUNT(*)`. Репозиторий читает `size + 1` строку, а API возвращает
  `X-Has-More` и, при наличии продолжения, `X-Next-Page`.

## Транзакции

Транзакции нужны в нескольких сложных операциях:

1. Завершение попытки квиза сохраняет ответы и результат, начисляет опыт и рейтинг.
   Частичное сохранение сделало бы повторную отправку некорректной.
2. Отправка уведомления атомарно резервирует ключ дедупликации, сохраняет уведомление
   и создаёт записи доставки. Без транзакции параллельные триггеры могли бы создать
   дубликаты.
3. Принятие заявки в друзья и изменение состава соревнования проверяют текущее
   состояние перед записью. Транзакция сохраняет проверку и изменение как одну
   операцию.

## Проверка качества

- JUnit Jupiter используется для модульных и интеграционных тестов.
- PostgreSQL-интеграции проверяются Testcontainers; тесты отмечены
  `@Testcontainers(disabledWithoutDocker = true)`.
- JaCoCo проверяет общий порог покрытия 70%, исключая сгенерированный OpenAPI-код.
- CI выполняет `openApiValidate`, тесты, проверку покрытия и сборку.
- Локальный полный прогон: `./gradlew test openApiValidate build`.
- Полное окружение: `docker compose up --build`.

## REST и ошибки

Контроллеры реализуют интерфейсы, сгенерированные из общего OpenAPI 3 контракта.
DTO контракта отделены от JPA-сущностей. Jakarta Validation проверяет входные DTO,
а ограничения сущностей и БД защищают сохраняемые данные. `GlobalExceptionHandler`
преобразует доменные ошибки и ошибки валидации в единый человекочитаемый JSON.
